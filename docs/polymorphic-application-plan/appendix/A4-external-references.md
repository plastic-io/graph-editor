## MCP (fetched from modelcontextprotocol.io, 2026-09-20)
- Current spec revision: **2026-07-28** (schema: github.com/modelcontextprotocol/specification/blob/main/schema/2026-07-28/schema.ts). Pages: /specification/2026-07-28/{basic/transports, basic/transports/streamable-http, basic/authorization, basic/patterns/subscriptions, basic/patterns/cancellation, basic/patterns/mrtr, server/tools, server/resources, server/utilities/pagination}; extension: /extensions/tasks/overview (spec at github.com/modelcontextprotocol/ext-tasks).
- 2026-07-28 changes vs 2025-xx: **no protocol-level sessions** (no Mcp-Session-Id), **no standalone GET SSE stream**, every request is its own POST carrying `_meta.io.modelcontextprotocol/{protocolVersion,clientInfo,clientCapabilities}`; header `MCP-Protocol-Version` MUST match body; `Mcp-Method` and `Mcp-Name` headers REQUIRED; server-initiated requests are gone — sampling/elicitation are Multi Round-Trip Requests (`resultType: "input_required"`, `inputRequests`, `requestState`); long-lived notifications only via `subscriptions/listen` (filter: toolsListChanged, promptsListChanged, resourcesListChanged, resourceSubscriptions[uri]; first message `notifications/subscriptions/acknowledged`); cancellation on Streamable HTTP = client closes the response stream; `Last-Event-ID` resumability removed; Origin validation MUST (403).
- Tools: `tools/list` (cursor pagination, deterministic order, `ttlMs`/`cacheScope`), tool def {name, title, description, inputSchema (JSON Schema 2020-12 default), outputSchema, annotations (untrusted), icons, x-mcp-header}; `tools/call` result {resultType:"complete", content[], structuredContent, isError}; "Servers MUST provide structured results that conform to this schema" when outputSchema given; protocol errors (-32602 unknown tool) vs execution errors (isError:true); tool names SHOULD be 1-128 chars of [A-Za-z0-9_.-]; servers MUST validate inputs, implement access control, rate limit, sanitize outputs; stateful handles are ordinary strings, server MUST re-authorize on every call.
- Resources: capability {subscribe, listChanged}; `resources/list`, `resources/read` (contents[{uri,mimeType,text|blob}], may return InputRequiredResult), `resources/templates/list` (RFC 6570); subscribe via `subscriptions/listen.resourceSubscriptions`; `notifications/resources/updated {uri}`; not-found MUST be -32602 (accept -32002 legacy); annotations {audience, priority, lastModified}; servers MUST validate URIs.
- Authorization (HTTP): OAuth 2.1 resource server; MUST implement RFC 9728 protected resource metadata; token audience MUST be validated (RFC 8707 `resource`); 401 with `WWW-Authenticate: Bearer resource_metadata=..., scope=...`; 403 `insufficient_scope`; "MCP servers MUST NOT accept or transit any other tokens"; tokens MUST be in Authorization header, never query string.
- Tasks extension `io.modelcontextprotocol/tasks`: server returns `resultType:"task"` {taskId, status, ttlMs, pollIntervalMs}; states working|input_required|completed|failed|cancelled; `tasks/get`, `tasks/update`, `tasks/cancel` (cooperative), `notifications/tasks` via subscriptions/listen. Fits Lambda-bounded long operations (deployments).
- TypeScript SDK: the 1.x line `@modelcontextprotocol/sdk` (latest 1.30.0) implements only pre-2026-07-28 (session-based) protocol; the 2026-07-28 revision is implemented by the SDK v2 packages `@modelcontextprotocol/server` and `@modelcontextprotocol/client` (2.0.0 beta line; see release notes github.com/modelcontextprotocol/typescript-sdk/releases: 'first beta release of SDK v2 with support for the MCP 2026-07-28 specification revision'). Versions/dates on npm recorded below.

## AWS quotas (docs.aws.amazon.com, fetched 2026-09-20)
- API Gateway WebSocket: connection duration max 2 h; idle timeout 10 min; frame 32 KB; message payload 128 KB (apigateway-execution-service-websocket-limits-table.html; not increasable).
- API Gateway REST: integration timeout 50 ms–29 s, raisable above 29 s only for Regional/private APIs via quota L-E5AE38E3; payload 10 MB; idle connection timeout 310 s (api-gateway-execution-service-limits-table.html).
- Lambda: function timeout max 900 s; sync payload 6 MB request/response; streamed response 200 MB (gettingstarted-limits.html).
- Consequence for MCP on this stack: a REST-API-fronted Lambda cannot hold `subscriptions/listen` SSE streams beyond 29 s; options are (a) Lambda Function URL with response streaming (≤15 min, 200 MB), (b) Tasks-extension polling, (c) bridging notifications over the existing WebSocket API (custom transport). See plan §MCP transport decision.

## AWS behaviour verified for the IaC design (fetched 2026-09-20)
- S3 conditional writes: `If-None-Match: *` (create-if-absent) and `If-Match: <etag>` on PutObject / CompleteMultipartUpload / CopyObject; precondition failure → `412 Precondition Failed`; concurrent delete → `409 Conflict` (If-None-Match) or `404` (If-Match); requires SigV4 (docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html). Usable as the per-stack and per-revision lock/CAS primitive without adding DynamoDB.
- Step Functions `StartExecution` is idempotent for STANDARD workflows: same `name` + same input while running → same response; same name with different input, or after close → `400 ExecutionAlreadyExists`; names reusable 90 days after close (API_StartExecution.html). Name ≤ 80 chars, [0-9A-Za-z_-] recommended.
- CloudFormation → EventBridge: detail-types `CloudFormation Stack Status Change`, `CloudFormation Resource Status Change`, `CloudFormation Drift Detection Status Change`; detail has `stack-id`, `logical-resource-id`, `resource-type`, `status-details.{status,status-reason}`; at-least-once delivery (cfn-eventbridge.html).
