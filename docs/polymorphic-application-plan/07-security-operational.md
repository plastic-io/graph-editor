# 7. Security and operational design

## 7.1 Threat model
Trust boundaries: B1 external HTTP client→API Gateway; B2 browser replica (Y.Doc + local scheduler)→WS; B3 MCP client→`/mcp`; B4 model-generated content (ops, rationale, descriptions)→admission; B5 admission→S3 authoritative prefixes; B6 replication→other browsers; B7 registry/S3 artifacts→import; B8 scheduler→host bindings; B9 persistence (S3, IndexedDB)→recovery; B10 orchestration roles→AWS.

| ID | Threat | Asset | Precondition | Path | Current protection [FACT] | Proposed enforcement point | Residual risk | Negative test |
|---|---|---|---|---|---|---|---|---|
| T1 | Unauthorized structural edit | graph definition | reach WS/REST | send update for any `graphId` | none (GS-05, all routes `NONE`) | `$connect` authorizer + REST authorizer; ACL check in `admit()` before staging | policy bugs | anonymous `yjs` frame → socket closed 401; foreign graph → `ADMISSION_DENIED`, S3 unchanged |
| T2 | Raw CRDT injection / poisoning | trusted doc, replicas | as T1 | garbage or destructive V2 bytes | none; verified poisoning (GS-13) | decode guard + size/struct caps + staging diff + namespace rules | Yjs decoder bugs → cap + timeout; `allowClear` policy | replay the poisoning frame → rejected; `GET /crdt/{id}/state` 200 |
| T3 | Identity spoofing | audit, ACL | any client | forged `sub`/awareness user | awareness user is self-declared (GE-26) | principal from token only; awareness `user` overwritten server-side from the connection principal | token theft (mitigated by short TTL, audience) | envelope with `principal` field → ignored; audit shows token sub |
| T4 | Confused deputy via server execution | Lambda role (S3 r/w/d, secret, ManageConnections) | reach `ANY /{proxy+}` | node code with `AWS`/`require` (GS-29, F.6) | none | capability host + isolated-vm; endpoints registered only at activation with owner principal; execution principal = endpoint owner's grants | isolated-vm CVEs; host binding bugs | node calling `require('fs')` → `ReferenceError`; `AWS` undefined; observation `effect.denied` for unscoped `host.fetch` |
| T5 | Capability laundering via recursion/hyperedges | effect authority | `component:publish` | nested component requests wider caps; rewire into privileged node | none | intersection rule; `graph:connect-privileged` for edges into privileged nodes; manifest validation at publish | mis-scoped grants by owners | nested `aws:*` under parent `net:https` → publish rejected; connect into `secret` node without permission → `CAPABILITY_MISSING` |
| T6 | Cross-tenant access (UUID guessing, TOC listing) | other tenants' graphs | know/guess id | GET/subscribe | none; TOC is global (GS-22/23) | tenant on TOC entries and ACL docs; subscribe authorization; TOC broadcast per tenant channel | id leakage in logs | tenant A lists/subscribes → no tenant-B data or channel |
| T7 | Prompt injection in descriptions/observations/rationale | agent behaviour | can edit text | instructions in metadata | inherent | MCP results mark free-text fields `untrusted:true` and wrap them; approvals of privileged ops require a human token; tool descriptions are static | model compliance | description containing "approve and deploy" → no state change without a human `proposal.decide` |
| T8 | Secrets in traces | secrets | `graph:observe` | node emits secret on an edge / in `console` | `openai` key in `this` (GS-42); no redaction | `secretRef` handles only; redaction classes; `capture:meta` default; console → observation with same redaction | mislabelled ports | port `redaction:secret` → observation payload `[redacted]`; `host.secret(ref)` never returns the string |
| T9 | Supply chain via registry / imported artifacts / scripts | code execution | control unpkg package, S3 artifact, `properties.scripts` URL (GE-42) | import or open graph | none; `remoteConfiguration` can rewrite prefs (GE-30) | digest pins; `properties.scripts` removed from node/graph (replaced by declared `deps` with SRI hashes, admitted with `graph:connect-privileged`); `remoteConfiguration` limited to allow-listed keys | registry compromise before pin | tampered artifact → `INTEGRITY_FAILURE`; script without SRI → rejected |
| T10 | Replay / duplicate delivery | history integrity | network position | resend envelope | none (A2 D.7) | `mutationId` idempotency (`If-None-Match:*`) | — | replayed envelope → original ack, single S3 object |
| T11 | Approval substitution | policy | proposer | edit after approval | none | approval binds `proposalDigest`+base+policyVersion; commit recomputes | — | modify then commit → `APPROVAL_REQUIRED` |
| T12 | TOCTOU validate→commit | policy | concurrent writer | head moves | none | HEAD CAS (`If-Match`) + re-validation at commit | — | two commits same base → one `STALE_BASE` |
| T13 | Resource exhaustion (loops, recursion, fan-out storms, observation floods, oversize updates) | availability, cost | `graph:execute` or `graph:propose` | node code / big updates | Lambda 30 s only; browser none; Rust fatal OOM (RT-35) | budgets, watchdog termination, isolate memory limit, update size caps, observation caps, tenant buckets | native stuck work (abandon path) | `while(true)` stopped ≤ wall+100 ms; 10 MB update → 413/`SCHEMA_INVALID` |
| T14 | Privilege escalation through IaC | AWS account | `iac:propose` | template with admin IAM, custom resource, macro, cross-account resource policy | no IaC exists | validator deny-list; permissions boundary; `CAPABILITY_NAMED_IAM` needs human approval; exec role denies on substrate stacks | CloudFormation feature gaps | fixture templates: unbounded IAM, `Custom::X`, `Principal:"*"` → validation failures |
| T15 | Agent gains authority via a different client | policy | agent token | use WS instead of MCP | n/a | one principal resolver for both; grants from delegation records only | — | agent token over WS → same denials |
| T16 | Browser obtains server-only values | secrets, credentials | any viewer | subscribe/doc dump | none needed today (no secrets in doc) | secrets never in doc; placement validator; `edge.deliver` payload = wireValue only | leakage through observation payloads (T8) | doc dump + observation stream contain no `secret` values |
| T17 | Malicious component publisher | consumers' graphs | `component:publish` | publish a "utility" with `net:https *` | none | consumers see capability requirements before import; grants are per instance; deprecation + revocation lists | social engineering | import shows required caps; instance grant defaults to none |
| T18 | Forged fan-out frames | replicas' docs | any socket | `sendToChannel` (GS-06) | none | remove client-callable `sendToChannel/sendToConnection/broadcast/listSubscriptions`; fan-out only from services | — | route removed → `$default` → not an execution request either (unknown action → 400) |

Assumptions under which the design is acceptable: Auth0 is trusted for identity; isolated-vm's isolate boundary holds for JS-only code (no native modules inside); S3 conditional writes provide the CAS semantics documented by AWS; the browser is the user's own agent and is not a containment boundary; CloudFormation honours the execution role and permissions boundary. Preventive controls: admission, capability host, budgets, IAM. Detective controls: audit chain, observations, drift reports, journey probes.

## 7.2 Authorization matrix and decision procedure

| Operation | Required authority | Inputs to decision | Policy source | Audit event | Rejection | Tests |
|---|---|---|---|---|---|---|
| read structure/metadata | `graph:read` | principal, graphId, tenant | `policy/graphs/<id>/acl.json` | none (rate-limited) | `NOT_FOUND` (no existence disclosure) | ACL table tests |
| read code / nested internals | `graph:inspect-internals` | + nodeId | same | none | `ADMISSION_DENIED` | |
| observe events / payloads | `graph:observe` / `graph:inspect-payloads` | + subscription filter | same + port redaction | `observe.subscribed` | subscribe refused | redaction tests |
| propose | `graph:propose` | diff namespaces, privilege delta | acl + `policy/rules.json` (per-namespace review rules) | `mutation.proposed` | `ADMISSION_DENIED` | |
| approve | `graph:approve` (not self unless `selfApprove`) | proposalDigest, base, policyVersion | same | `proposal.decided` | `ADMISSION_DENIED` | |
| commit | `graph:commit` (+ approvals if rules require) | diff, approvals | same | `mutation.committed` | `APPROVAL_REQUIRED`/`STALE_BASE` | |
| publish | `component:publish` | manifest, cycle check | same | `component.published` | `CONFLICT`/`SCHEMA_INVALID` | |
| execute / invoke | `graph:execute` + effect caps at runtime | revision, entry, budget | acl + instance grants + revocations | `execution.started` + effects | `BUDGET_EXCEEDED`, `effect.denied` | adversarial suite |
| connect privileged edges | `graph:connect-privileged` | diff `edges.added` into nodes with server/secret/aws caps | same | in `mutation.*` | `CAPABILITY_MISSING` | |
| activate / rollback | `graph:activate` / `graph:rollback` | revision, unresolved check, schema gate | same | `revision.activated` | `UNRESOLVED_COMPONENT`, `UNSUPPORTED_SCHEMA` | |
| IaC plan/apply/cancel | `iac:propose` / `iac:approve` | desired state, env policy, plan.destructive | `policy/iac/<env>.json` | `iac.*` | `APPROVAL_REQUIRED` | fixture templates |
| policy edit (ACL, delegations) | `policy:admin` | target principal, scopes ⊆ own | `policy/` (never the doc) | `policy.changed` | `ADMISSION_DENIED` | self-broadening test |

Decision procedure (`src/policy/decide.ts`): (1) authenticate → principal or 401; (2) resolve tenant and delegation (agent: scopes ∩ delegator's grants; expired → 403); (3) load ACL and rules (cached per Lambda 30 s, versioned); (4) compute required authorities from the operation and the semantic diff (namespaces touched, privilege delta, edges into privileged nodes); (5) allow iff required ⊆ effective; (6) if rules mark the namespace as reviewed for this principal kind → `approval-required`; (7) emit audit with `policyVersion`; (8) runtime effects re-check (2)–(5) for the *capability* subset on every privileged host call, consulting the revocation list. Delegated authority is narrowed at each hop (intersection), never widened.

## 7.3 Resource enforcement, credentials, persistence, observability (operational)
- Enforcement locations: admission (`src/admission/*`), scheduler wrapper (`packages/GraphRuntime` shared, `src/runtime/*` server), `host` bindings, isolated-vm limits, Lambda config, tenant buckets, IaC validator/orchestrator.
- Credentials: humans via Auth0 (RS256, JWKS cached), agents via Auth0 client credentials + delegation records, server via the Lambda role (reduced: S3 prefixes split — request role gets `graphs/`, `revisions/`, `components/`, `audit/`, `policy/` with `s3:PutObject` conditions on prefixes; the IaC roles as §4.9.6), secrets via Secrets Manager referenced by `secretRef` and resolved only inside `host.secret`. Remove `secretsmanager:GetSecretValue` from the request role for the OpenAI key once `host.secret` exists (the key becomes a per-tenant secret).
- Persistence and recovery: S3 versioning, lifecycle (observations 14 d, updates folded into revision snapshots, audit forever), cross-region copy of authoritative prefixes, restore drill quarterly; TOC rebuild [FACT] as repair tool; revision digest verification job.
- Observability of the substrate: CloudWatch metrics per Lambda (admission decisions by code, staging latency, isolate terminations, OOMs, budget exhaustion, delivery backlog), alarms on rejection spikes and termination rates; Step Functions execution metrics for IaC; synthetic journeys (§8.2) as the application-level health signal.
- Residual risks accepted for the first releases: browser-side effects unpreventable; one isolate per root execution (sibling nodes share fate); no per-tenant Lambda isolation; Streamable HTTP subscriptions depend on spike S-3; Rust runtime not on the path.
